# dev-hub

本地项目启动管理平台。解决一件事：**项目多了以后忘记「在哪个目录、用什么命令启动」**。

登记一次，永久记住；打开面板就能看到所有项目在不在跑、占哪个端口、日志长什么样。

- **零依赖** —— 只用 Node 内置模块，不装任何 npm 包
- **不常驻** —— 前台运行，Ctrl+C 即停；平台关了，已启动的项目照常跑
- **不用 Docker** —— 直接在你本机跑，省内存

---

## 快速开始

```sh
cd ~/Documents/dev-hub
./start.sh
```

浏览器打开 **http://127.0.0.1:4321**

换端口：`PORT=4322 ./start.sh`

## 用法

### 1. 登记一个项目

点「**+ 新建项目**」，粘贴**一条自带 `cd` 的完整命令**：

```sh
cd ~/projects/my-api && npm run dev
cd "~/projects/with space/app" && ./scripts/start-local.sh
cd ~/projects/my-go-svc && go run . -addr :8100
```

> **为什么必须带 `cd`**：`npm run dev`、`go run .`、`./scripts/start-local.sh` 这类命令全都依赖
> 工作目录。平台从 `cd` 里解析出目录，才能正确执行、正确显示、正确匹配端口。

路径里有空格要加引号（`"~/projects/with space/app"`），或者用反斜杠转义（`with\ space/app`）。
`~` 也支持。

表单会实时回显解析出的执行目录，并把该目录下正在监听的服务端口列出来供你点选。
**端口一般不用手填** —— 启动后平台会自动探测并回填。

### 2. 日常使用

- **启动 / 停止 / 重启**：表格右侧按钮
- **看日志**：点「日志」，右侧抽屉实时滚动（1 秒一次）
- **状态灯**：🟢 运行中 · ⚪ 已停止 · 🔴 异常退出 · 🟠 外部运行中（进程不在平台名下，但端口有东西在听）

### 3. 停止命令（可选）

默认停止方式是**杀掉整个进程组**（`kill(-pgid)`），对绝大多数项目够用。

但如果你的服务有正规的停止姿势 —— 比如 `./scripts/stop.sh`、`launchctl unload`、
`docker compose down`、`nginx -s quit` —— 就在「编辑」里填进**停止命令**，平台会优先执行它。

```
停止命令：./scripts/stop.sh
```

行为：

1. 执行你的停止命令（在项目目录下，输出写进日志，最长等 30 秒）
2. 执行完**再确认进程是不是真的没了**
3. 如果进程还活着（脚本报错、或者命令写错了），**自动退回默认方式强制停止**，并在界面提示你

> 第 3 步是有意为之：宁可多停一次，也不要留下一个占着端口的孤儿进程，让你下次启动时莫名其妙失败。

**留空 = 保持默认行为**，不受影响。

### 4. 日志文件（可选）

默认情况下，平台把进程的 stdout/stderr 直接抓到自己管理的文件里，点「日志」就能看。

但如果你的项目**自己写日志文件**（`logs/app.log`、`nohup.out` 之类），在「编辑」里填上**日志文件**，
平台就改为实时滚动那个文件：

```
日志文件：logs/app.log      ← 相对项目目录，也可以填绝对路径或 ~/...
```

- 支持 `~` 和相对项目目录的写法
- 填了之后列表上会有「项目日志」标记，抽屉标题也会注明
- **这类外部日志的「清空」按钮会被禁用** —— 那是项目自己写的文件，平台不主动删

**留空 = 保持默认行为。**

### 5. 扫描导入现有服务

点「**扫描当前运行的服务**」，平台列出所有正在监听端口、且工作目录在你的项目目录下的进程，
勾选后一键导入。已经跑着的进程会被**直接接管**，平台立刻能显示它、也能停掉它。

**三个限制（很重要）**：

1. 拿到的是进程的**实际命令行**，不一定等于你当初敲的那条 —— `npm run dev` 会显示成
   `node .../vite.js`，`go run .` 会显示成 Go 的临时二进制路径。导入后建议改成原始写法。
2. **环境变量拿不到**（macOS 不允许读别的进程的 env），需要的话导入后手动补。
3. **只能发现此刻正在跑的进程**，已经停掉的扫不出来，只能手动登记。

### 6. 「接管」是什么意思

列表里带「接管」徽标，表示**这个进程不是平台启动的，平台只是知道它的存在**。

具体只有两种情况会被标记为接管：

| 来源 | 说明 |
|---|---|
| 扫描导入 | 你在终端里手动起的服务，通过扫描导入进来 —— 平台没启动它，只是接管了它的 PID |
| 平台重启后认回 | 平台上次启动过它，然后平台自己重启了；重新起来时发现那个 PID 还活着，就认回来 |

判断依据是 **PID 是否还活着**（`kill(pid, 0)`），再加上两道校验防止误认：

- 进程的**工作目录**必须和项目目录一致
- `ps` 拿到的**进程启动时间**必须和记录对得上（`ps` 不可用时跳过这条，并在界面标「未校验」）

两道都对不上就判定「原 PID 已被别的进程占用」，**主动解除绑定**，不会误杀别人的进程。

平台自己启动的项目不会有这个徽标。

### 7. 端口是怎么算的

一个项目常常同时开着好几个端口。实测的典型情况：

| 类型 | 例子 | 性质 |
|---|---|---|
| GUI 应用内部端口 | Electron / Chromium 的随机回环端口 | **纯噪音** |
| 真服务 | nginx 的 4173、java 服务的 8081 | 业务端口 |
| 管理端口 | 9876（JMX）、10000 以上的端口 | 不是业务 |

平台的规则：

- **每行只显示一个主端口**，其余折成 `+N`。鼠标悬停在端口上能看到完整清单（含被折叠的）。
- **默认折叠**：GUI 应用（Electron / Chromium）的内部端口；10000 以上的端口（JMX、监控、系统临时端口都在这一段）；已知中间件端口（Redis 6379、MySQL 3306、ZooKeeper 2181 等）。
- **主端口** = 最小的业务服务端口（小于 10000 且不属于中间件）。一个业务端口都没有时，才退而显示管理端口；只有 GUI 内部端口时显示 `—`。

**想让某个项目固定显示某个端口**：点「编辑」，表单下方会列出该目录下所有在跑的服务端口，点一下就钉住。

**前后端要分开管理**：建两条记录，各钉一个端口即可。钉了端口的记录**只认自己那个端口**，
不会跟同目录的另一条互相干扰（状态灯、端口冲突检测都按各自钉住的端口判断）。

### 8. 端口是唯一键

一个端口只能被一条记录认领。这条规则落在四个地方：

| 场景 | 行为 |
|---|---|
| 扫描导入 | 端口已被认领的候选**自动去重、默认不勾选**（悬停徽标看被谁占了）；即使手动勾上，导入时也会被跳过并告诉你原因 |
| 新建 | 填的端口已被别的记录认领 → 直接拒绝 |
| 编辑 | 同上 |
| 启动后自动探测 | 只会回填给**还没认领端口**的记录，绝不覆盖你钉过的端口，也不会抢占别人的端口 |

> 用端口而不是目录做主键，是因为「前后端拆两条」正是**同目录、不同端口** —— 按目录去重会挡掉这种用法。

## 设计要点

| 问题 | 做法 |
|---|---|
| 平台关了，项目还能跑吗？ | 能。子进程 `detached` 独立成新会话，stdout/stderr **直连日志文件 fd**（不用 pipe —— 用 pipe 的话平台一退出子进程会吃 SIGPIPE 死掉） |
| 停止时怎么不留孤儿进程？ | `detached` 让子进程成为进程组组长，`kill(-pid)` 一次干掉整棵树。只 kill 父 PID 的话，`npm run dev` 派生的子进程会变孤儿继续占端口 |
| 平台重启后还能认回项目吗？ | 能。PID 存活 + 进程 cwd + `ps` 启动时间三重校验，防止 PID 被系统复用后误认、误杀 |
| 端口怎么知道？ | 按工作目录反查监听端口（`lsof`），不依赖 `ps`，对终端手动启动的进程同样有效 |
| 数据在哪？ | `data/projects.json`（登记表）、`data/runtime.json`（运行状态）、`data/logs/<id>.log`（日志）。都是纯文本，可以直接改 |

## 目录结构

```
dev-hub/
├─ start.sh             启动脚本
├─ server.js            HTTP 服务 + 路由 + 静态托管
├─ lib/
│  ├─ store.js          projects.json / runtime.json 原子读写
│  ├─ cmdparse.js       从「cd 路径 && 命令」解析 cwd
│  ├─ process.js        拉起 / 杀进程组 / 自定义命令 / 内存与存活探测
│  ├─ ports.js          lsof 端口与进程归属探测
│  ├─ portclass.js      端口分类：把一堆监听端口收敛成主端口
│  ├─ logs.js           日志落盘、轮转、增量读取、外部日志文件
│  ├─ scanner.js        扫描运行中的服务
│  └─ api.js            业务逻辑
├─ public/index.html    单页前端
└─ data/                数据目录（首次运行自动创建）
```

## HTTP API

本地服务，只绑 `127.0.0.1`，不加鉴权（外部网络不可达，本机单用户）。

| Method | Path | 说明 |
|---|---|---|
| GET | `/api/projects` | 项目列表 + 运行状态 |
| POST | `/api/projects` | 新增 |
| PUT | `/api/projects/:id` | 修改 |
| DELETE | `/api/projects/:id` | 删除（**只移除记录，不杀进程**） |
| POST | `/api/projects/:id/start` | 启动 |
| POST | `/api/projects/:id/stop` | 停止（有停止命令就先执行它） |
| POST | `/api/projects/:id/restart` | 重启 |
| GET | `/api/projects/:id/logs?offset=N` | 日志增量 |
| POST | `/api/projects/:id/logs/clear` | 清空日志（外部日志文件会被拒绝） |
| GET | `/api/projects/:id/logs/download` | 下载日志 |
| POST | `/api/cmd/parse` | 解析命令里的 `cd` |
| POST | `/api/ports/by-cwd` | 查某目录下在监听的服务端口 |
| POST | `/api/scan` | 扫描运行中的服务 |
| POST | `/api/import` | 导入选中的候选 |

## 已知限制

- **内存占用依赖 `ps`**。如果 `ps` 不可用（比如某些受限环境），会降级到 `top`，再不行就显示 `—`，不影响其它功能。
- **扫描导入的命令不是原始命令**，见上文第 5 节。
- **接管来的进程，之前的日志拿不到** —— 那些输出在你的终端里，平台无法回溯。之后的新输出才会进日志文件（如果项目有自己写日志，可以填「日志文件」来解决）。
- 同一个目录下同时跑多个服务时，靠「钉端口」区分；不钉的话按最小业务端口显示。

## 环境要求

- macOS（依赖 `lsof` / `ps`，系统自带）
- Node.js 18+
